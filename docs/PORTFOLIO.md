# 简历与面试材料

## 简历版本

**Env AI Job Scout｜证据驱动的 AI 求职追踪工具**
技术栈：Python、SQLite、Codex 工作流、OOXML、PowerShell、GitHub Actions

- 构建“岗位发现—证据核验—资格分流—增量台账—Excel 跟进”的 AI 工作流，将非结构化信息提取与确定性规则校验分离。
- 设计基于原文引用、SHA-256、来源授权范围和时效的证据检查机制，结合三值资格判断，区分已核实可投、资格待确认、待核实及历史岗位。
- 使用 SQLite 管理去重岗位、历史观测和变更事件，以 Python 标准库生成 13 表 Excel，并在再次导出时回收人工状态、优先级和备注。
- 提供无需联网或模型账号的可复现演示，覆盖重复入库、伪造引文隔离与导出；建立离线回归测试和 Windows / Linux 持续集成流程。

项目地址：https://github.com/s1encisi/env-ai-job-scout

## 60 秒介绍

这个项目解决的是招聘信息“找到以后如何持续可信地管理”的问题。我把流程拆成两层：AI 负责查找页面和理解岗位文本，Python 负责确定性的证据、来源、时效与资格校验。数据保存在 SQLite，Excel 作为可重建的查看和跟进界面，人工备注会在下次导出前回收。核心设计是把“技能相关”和“资格通过”分开，并为未知条件保留明确状态。项目还提供纯离线的虚构演示，可以复现岗位去重、伪造引用隔离和 13 表导出。当前验证集中在规则与本地流程，真实网站的长期稳定性仍需进一步实测。

## 面试演示顺序

1. 运行 README 的测试与演示命令，说明样本全部虚构。
2. 查看 `demo-summary.json`，解释为什么重复写入后仍只有一个岗位。
3. 查看 `quarantine/`，展示无法匹配原文的引文如何被隔离。
4. 打开 Excel 的总览、证据索引和人工跟进，解释事实台账与派生视图的关系。
5. 展示 `test_52_manual_annotations_survive_reexport` 和资格未知测试，讨论实现取舍。
6. 解释 `partial`：没有执行真实搜索，即使导出成功也不宣称完成检索。

## 数据口径

可以引用源码可验证的 13 个工作表、12 行业 × 2 发现通道，以及验证报告中的实际测试结果。112 个企业种子只是搜索词；不能写成“已服务 112 家企业”或“核实 112 个岗位”。没有真实对照实验前，不填写效率提升、准确率、求职成功率、成本下降或用户规模。AI 辅助开发的贡献应按本人实际工作描述，不承诺“全部独立手写”。
